# Immersive construction rule

For reference-driven or premium immersive work, consult `docs/IMMERSIVE_CONSTRUCTION_INTELLIGENCE.md` before implementation.

Non-negotiable behavior:

1. Deconstruct the reference into composition, typography, depth, motion, continuity, interaction, DOM/WebGL roles, mobile translation and first-use performance costs.
2. Map those principles onto existing Forge systems before proposing a new dependency.
3. A dependency is never the answer to "make it feel like this reference" unless Forge genuinely lacks the required technical primitive and the trade-off is documented.
4. Preserve originality: transfer the construction principle, not the reference's exact palette, typeface, branded assets, copy or signature composition.
5. Name the visual anchor carried across every important transition.
6. Name the single highest-intensity signature moment and protect contrast around it.
7. Keep semantic content and conversion controls in DOM.
8. Preserve the concept on mobile; reduce rendering cost before deleting the defining idea.
9. Treat cold-scroll smoothness as part of visual quality. Prewarm expensive signature states when needed.
10. Do not create an independent animation clock; use the existing Forge timeline, motion tracks, cinematic ticker or interaction graph.
